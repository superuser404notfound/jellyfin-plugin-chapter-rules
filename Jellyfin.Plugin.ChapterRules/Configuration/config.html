Segment types

Which segment types may be derived from chapter positions. A type is only ever produced for a series where calibration found a rule that agrees with the segments already known for that series.

Skip a type for an episode when another provider already supplies it. Detection based providers usually put the boundary a few seconds earlier than the chapter marker — at the start of the fade rather than where the credits card appears — which is the nicer place to skip from. Leave this on unless you want chapter rules to take precedence.

Calibration

Share of comparison samples a rule must reproduce before it is used. 0.75 means the rule has to agree with three out of four known segments. This is a floor, not the real gate — the deviation limit below does the discriminating work.
At least nine in ten episodes must land within this of where the existing segment says the boundary is. This is the setting that separates a rule that is right but compared against fuzzy references from one that is anchored on the wrong chapter — confidence alone cannot tell them apart, because both look like "agrees with roughly four out of five".
How many known segments a series needs before any rule is trusted for it. Series below this are reported but never written to.
How far a derived boundary may sit from a known one and still count as a match.

Plausibility windows

A rule is skipped for an episode when the segment it would produce falls outside these lengths. This is what stops a chapter that happens to sit near the end of a file from being read as an eight minute outro.
